# Rearranging the panel yourself

Everything on the device's face is described in three files: **where** it is
(`panel_spec.py`), **what is drawn behind it** (`panel_body.sksl`) and **what the
parameters do** (`spec.py`). Nothing is hard-coded in the compiled device, so you
can move things, look at the result in a browser and rebuild in about a minute.

```
device/panel_spec.py   the face: sections, meters, knobs, captions, coordinates
device/panel_body.sksl the drawing the spec cannot express (gate LED, custom art)
device/panel.sksl      generated by gen_panel.py — do not hand-edit
device/spec.py         parameter ranges, defaults and their Nitro ports
tools/nam4nitro.py     the DSP
```

The spec is a `bwui` panel: an 87 x 53 grid of native Bitwig widgets plus the
shader bodies behind them. `document.py` turns it into document items and binds
each one to its parameter.

## Look at it without Bitwig

```sh
cd device
PY=../../ress-vocal/devkit/.venv/bin/python      # bwui is on this venv's path
"$PY" -m bwui check   panel_spec.py              # bounds, collisions, duplicate widgets
"$PY" -m bwui preview panel_spec.py --png /tmp/panel.png
"$PY" -m bwui edit    panel_spec.py -o /tmp/panel-editor.html   # drag widgets, snap, undo
"$PY" -m bwui edit    panel_spec.py -o /tmp/panel-editor.svg    # same editor as one SVG
"$PY" -m bwui code    /tmp/panel.layout.json -o panel_spec.py   # layout JSON back to code
```

The editor page is a single file: drag widgets, resize them from the eight
handles around a selection, add new ones from the palette, nudge with the arrow
keys and press **Download layout JSON**, then run
`bwui code` on it — that writes a `panel_spec.py` with one explicit call per
widget. `bwui svg panel_spec.py -o
panel.svg` gives the same face as a layered SVG for Figma, named by widget.

The HTML has 1x/1.6x/2.5x zoom, a grid overlay and a "Boxes" view that outlines
every widget with its coordinates. Rectangles in the preview are the exact
integers written into the device; the knob faces are an approximation.

## The coordinate system

The panel is **87 grid units wide and 53 tall** (Bitwig fixes the height; width
you can change). One unit is about 19 px at 150 % UI scale, and 469/87 px in the
shader's design space, so the whole panel is 469 x 286 design pixels. Positions
are `(x, y)` with **y down from the top-left of the panel**, and the document
stores **whole units** — `6.4` becomes `6`.

```python
# panel_spec.py
PANEL.knob("input", 3.0, 39.6, label="In")          # cell 6.4 x 6.4, caption centred below
PANEL.knob_row(y=39.6, x=3.0, knobs=[("input", "In"), ("gate", "Gate")], gap=1.2)
PANEL.knob_column(75.0, 7.0, [("treble", "Treb"), ("mid", "Mid"), ("bass", "Bass")], gap=6.1)
```

Rows and columns compute the spacing from the widget cell and the caption box, so
moving a knob means changing one number, and captions never need hand-placing.
Widgets may touch; a real overlap is reported by `bwui check` and by the build's
preflight (a warning).

A knob's rectangle is the **cell** it occupies, not the drawn knob: the `size`
argument (0-3) picks Bitwig's drawing size inside that cell.

## The background

`panel.sksl` is generated. `gen_panel.py` draws the background gradient, every
`PANEL.section(...)` body and edge, and every `PANEL.meter(...)` bar from the
spec, then appends `panel_body.sksl` for everything else — in the same design
pixel space, so a coordinate from the mockup can be used directly.

```python
# panel_spec.py: a body, and a meter fed by audioLow.x
PANEL.section("input well", (0.52, 0.72, 11.87, 35.74), style="well")
PANEL.meter("in", (3.86, 1.86, 2.41, 33.23), lane=0)
```

## Rebuild

```sh
cd ~/Documents/deepseek-harness/default-workspace/ress-amp
./build.sh              # regenerate panel + DSP, build, install, run preflight
```

Then in Bitwig: **delete the old device from the track and insert a fresh one** —
a device already on a track keeps the compiled code it was inserted with, so the
file on disk can change without the instance changing.
